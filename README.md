# 本地 OCR · Local OCR

一款适用于 Windows 和 Linux 的本地文字与表格识别工具，支持图片、PDF 批量处理，以及识别后的校对、文本整理和导出。

**文档在本机处理，不上传到在线识别服务。** 模型可提前联网下载，准备完成后即可离线使用。

当前版本：**0.14.5**。

## 主要功能

- **文字与表格识别**：提供快速、高精度文字模型档位；表格模式支持行列、合并单元格及符合条件的跨页表格合并。
- **图片与 PDF 批量处理**：支持指定 PDF 页码、图片旋转、自然文件名排序、暂停、继续及页级断点续识。
- **PDF 直接取文**：优先提取可用文本层，扫描页使用 OCR；文本层异常时可选择强制 OCR。
- **文本智能整理**：连接正文版面断行，整理中日英标点、空格与空行；表格逐单元格清洗并保留结构，支持整理前后对照。
- **日语注音处理**：支持横排、竖排注音，提供忽略注音、括号标注、HTML Ruby 小字三种输出。
- **查看与校对**：可编辑文字、复制表格到电子表格软件；专注模式支持整理前后双栏对照。
- **导出与历史**：自由组合 TXT、XLSX、HTML，支持自动导出与识别历史恢复。

## 下载与运行

在本仓库 **Releases** 页面下载适合系统的程序，无需自行安装 Python 或 PaddleOCR。

| 平台 | 下载版本 |
| --- | --- |
| Windows x64 | `.exe` 安装程序（NSIS） |
| Linux x64 | 普通版 `.AppImage`，使用 WebKitGTK 4.1 |
| 需要旧版运行库的 Linux x64 | WebKitGTK 4.0 兼容版 `.AppImage`，最低 glibc 2.28 |

两个 Linux 版本选择其一。普通版无法运行、提示 WebKitGTK 或 GLIBC 不兼容时，可尝试兼容版；兼容版也不保证适用于所有发行版。

Linux 首次运行前，在文件属性中允许作为程序执行，或使用：

```bash
chmod +x 软件文件名.AppImage
./软件文件名.AppImage
```

Windows 如提示缺少 WebView2，请按程序提示安装运行库；离线安装方法见[离线使用说明](docs/OFFLINE.md)。

## 快速开始

1. **选择识别方式**：普通文字或表格与文字，再选择快速或高精度档位。使用 OCR 前点击“准备当前模型”；纯文本 PDF 可直接取文，无需 OCR 模型。
2. **添加文件**：选择或拖入图片、PDF。按需设置页码和图片方向。指定页码如 `1,3-5,8`，按 PDF 实际页面顺序计算，不是正文印刷页码。
3. **开始识别**：按队列顺序处理，可查看已完成结果。暂停、取消通常在当前页完成后生效。
4. **校对并导出**：切换“整理前 / 整理后”查看，选择导出范围、文本版本及格式，再导出文件。

如需自动保存到指定文件夹，在开始前勾选“每个文件完成后自动导出”，选择格式与目录。导出失败可单独重试，不必重新识别。

### 结果保存与恢复

任务、已完成页面及校对内容会自动保存在本机。清理已结束任务或移除队列项后，可从 **“批量任务 → 识别历史”** 找回已保存的结果，查看、复制或导出；不要求原文档仍在原位置。

- 未完成任务重试时，原文件与识别设置一致，可跳过已保存页面继续识别。
- 手工校对内容受到保护，不会因切换整理设置而自动改写。
- 原文预览切换不改变导出版本，导出时请留意自己的选择。
- 历史默认保留，彻底清除需在识别历史中执行“永久删除”。

**本机历史不是独立备份。** 清除应用数据会丢失记录；断电或强制退出可能丢失尚未保存的内容。重要结果请导出到自己的文件夹。普通 Linux 版与 WebKitGTK 4.0 兼容版的历史数据不自动互通。

## 在离线电脑使用

1. 在联网电脑打开 **“模型管理 → 在离线电脑上使用”**，选择需要的模型组合，点击“准备并导出模型”。
2. 将导出的整个 `LocalOCR-models` 文件夹，以及目标系统的软件安装包或 AppImage，一并复制到离线电脑。
3. 在离线电脑点击“从本地导入模型”，选择模型包根目录；验证通过后即可使用。

模型包不包含原文档、识别结果或历史记录。详细步骤及运行库问题见[离线使用说明](docs/OFFLINE.md)。

## 使用边界

- 识别效果受清晰度、字体、排版和拍照畸变影响，重要内容请人工校对。
- 表格识别侧重结构与文字，不还原 Excel 公式、原始字体、颜色或精确列宽。跨页合并采用保守规则，无法可靠判断时保留为独立表格。
- 日语注音绑定、段落连接及标点整理可能误判，可对照原始结果检查；部分缺少版面信息的旧结果不能使用完整整理功能。
- 识别和本地试识别期间启用 Python 网络连接限制，但这不等同于系统防火墙。需要整机断网时，请使用系统网络设置。
- 历史结果存储在本机，未加密。

## 从源码构建

项目采用 **Vue 3 / TypeScript + Tauri + Python / PaddleOCR sidecar**。Windows 与普通 Linux 版使用 Tauri 2，WebKitGTK 4.0 兼容版使用 Tauri 1。

推荐使用仓库内的 GitHub Actions 工作流：

1. 将完整源码上传到仓库根目录，包含 `.github` 目录。
2. 打开 **Actions → Build Windows and Linux x64 → Run workflow**。
3. 构建完成后，在该次运行的 Artifacts 中下载对应平台产物。

工作流生成 Windows NSIS、Linux 普通 AppImage、Linux WebKitGTK 4.0 兼容 AppImage 三种程序。具体依赖、测试与打包步骤见[构建工作流](.github/workflows/build-desktop.yml)。本地构建也应使用对应平台的环境与原生依赖。

推送 `v*` 标签也会触发构建，例如 `v0.14.5`。**当前工作流只上传 Actions Artifacts，不自动创建 GitHub Release。** Artifacts 保留 14 天；正式发布时，将解压后的安装程序和 AppImage 上传到 Release 附件。

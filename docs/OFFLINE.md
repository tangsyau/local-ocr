# 在离线电脑使用本地 OCR（0.8.x / 0.9.0）

## 联网电脑准备

1. 安装/打开 0.9.0，进入“模型管理 → 在离线电脑上使用”。0.8.x 已导出的模型包可继续使用，无需重新下载。
2. 勾选离线电脑需要的能力：轻量文字、高精度文字、表格＋轻量文字或表格＋高精度文字。不必全选；表格选项已经包含对应文字模型，共用文件只导出一次。
3. 点击“准备并导出模型”，选择保存位置。已完整下载的模型会复用；缺失模型下载后会用内置样张试识别，文档不会参与模型迁移。
4. 等待提示“已导出”。保存位置会出现 `LocalOCR-models`，已存在同名目录时自动编号，不覆盖旧包。完整复制文件夹，不要只复制 `model-pack.json`。
5. 同时下载目标电脑对应的软件包：Windows x64 安装程序、常规 Linux x64 AppImage，或 WebKitGTK 4.0 / glibc 2.28 兼容 AppImage。不能只复制已安装目录中的主 EXE，也不能用 Windows 安装包在 Linux 上运行。

如果导出被取消，未完成的导出临时目录会清理，但已经下载到本机的官方模型缓存会保留，便于下次继续准备。文件复制与 SHA-256 计算阶段显示百分比；模型下载来源不提供可靠总量时只显示阶段，不虚构进度。

## 离线电脑导入

1. 安装或打开适合本机系统的软件。
2. 在“模型管理 → 在离线电脑上使用”点击“从本地导入模型”，选择包含 `model-pack.json` 的模型包根目录。
3. 确认只导入可信来源的包。文件校验和用于检测损坏，不提供发布者身份认证；不要导入陌生来源的模型配置/权重。
4. 软件检查模型清单、版本、文件大小、SHA-256、磁盘空间，在临时目录内完成真正的本地文字/表格试识别，然后导入本机缓存。同名模型只有验证成功后才替换；失败会尝试回滚，其他模型不改动。
5. 导入成功后自动开启“仅使用本地模型”，并选择包中包含的一组能力。点击“准备当前模型”或开始识别即可。模型已复制进本机，之后可以拔掉 U 盘。

导入默认缓存位置：Windows 为 `%USERPROFILE%\.paddlex\official_models`；Linux 为 `~/.paddlex/official_models`。不要求两台电脑用户名、盘符或目录相同。以后删除当前缓存会使相应能力不可用，需要重新导入或到联网电脑准备。

开启“仅使用本地模型”后，准备时会显式使用本地模型路径；缺少某个档位会列出缺失模型并提示重新导入，不会回退到联网下载。导出功能则明确面向联网电脑，必要时仍会下载所勾选的模型。

## 可能遇到的问题

- **没有导入入口**：请使用本版软件；旧版不能读取本版的模型包清单。
- **文件缺失、校验失败**：重新完整复制模型包；不要修改清单或把不同版本的模型混在一起。旧缓存不会在校验阶段被覆盖。
- **磁盘不足**：导入需要额外空间先保存一份完整临时副本，已有同名模型要等验证完成才替换。选择空间充足的磁盘。
- **版本不兼容**：0.8.0 的模型包声明 PaddlePaddle 3.2.2、PaddleOCR 3.7.0、PaddleX 3.7.2；程序会拒绝不匹配的清单。模型文件不含 Python 或系统动态库，仍需对应平台的软件包；跨平台搬运要以目标端试识别通过为准。
- **导入很慢**：首次原生依赖载入、安全软件扫描、U 盘读速和高精度模型内存占用均会增加耗时。可取消迁移；短暂的提交阶段不可取消，请勿强制关闭。异常断电不能保证多目录事务；若提示自动回滚失败，保留提示中的备份目录用于恢复，不要自行清理。
- **Windows 提示缺少 WebView2，或安装程序无法下载它**：在联网电脑从[微软官网](https://developer.microsoft.com/microsoft-edge/webview2/)下载 Evergreen Standalone Installer 的 x64 版本，复制到离线电脑后安装，再运行本软件。不要选需要联网的 Bootstrapper。本版不把这个少见依赖再打成大安装包。
- **Linux 报 GLIBC/WebKitGTK 不兼容**：换用匹配系统的版本。兼容版目标最低 glibc 2.28；复制模型不能修复系统运行库不匹配。

## 隐私范围

模型包只包含指定模型的推理配置、模型权重、清单及本说明摘要，不包含原文档、识别文字、历史记录、个人路径或日志。识别不使用云 OCR；推理与本地试识别期间启用 Python socket 网络守卫，但它不是操作系统防火墙。如需验证整机零联网，请在目标电脑断网或由系统网络策略限制后测试。

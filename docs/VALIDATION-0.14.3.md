# 0.14.3 验证记录

## 问题与范围
用户反馈 WebKitGTK 4.0 版本整理后仍为原文。源码检查发现清洗模块依赖 String.matchAll；旧内核可能缺少该 API，Vite 的编译目标不提供运行时 API 补齐。此次移除该依赖，使用克隆正则的 exec 迭代，并保留 Unicode 零长度匹配推进保护。

这是一项兼容性修复，不代表已经在用户机器确定唯一根因。缺少版面信息的旧结果、手动校对保护、原文视图和原始整理模式也会保留原文，均维持原有行为。

## 验证
- 118 项前端测试通过，包括删除 String.matchAll 后实际执行中文整理、连接断行、英文 Markdown 标点、代码保护与原文对照。
- 11 项 Python 项目配置测试通过。
- 普通与 WebKitGTK 4.0 前端构建通过。
- 安装包 CI 的现有桌面握手现在必须通过真正 WebView 内的文本整理结果校验，不再只检查窗口和 sidecar 就绪。
- 复制诊断信息增加不含文本的 textProcessing 字段，用于区分设置、历史数据与运行时问题。

## 未验证项
当前环境没有旧版 WebKitGTK；没有本地生成原生安装包，也未宣称目标系统测试通过。须由 GitHub Actions 和目标机器继续验证。

## 目标机检查
选择普通文字、智能整理与整理后视图，使用已知含多余空格及断行的新识别结果。确认清洗和复制/导出一致。若仍无变化，在该结果选中时复制诊断信息：runtimeCheck 应为 true；检查 textMode、rawView、edited、layoutPageCount。保留校对稿，不为排障盲目丢弃结果或重跑全部文档。

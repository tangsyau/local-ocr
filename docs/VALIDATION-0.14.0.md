# 0.14.0 验证与验收

## 本次改动

识别历史与当前队列分离，使用原有 IndexedDB 数据库的独立历史记录键，逐页结果仍独立存储。每次自动保存以事务更新历史摘要与页面；移除队列项先保存，再仅移除队列引用。原有 schema-1 队列按现有迁移流程写入逐页记录，schema-2 保持兼容。

历史列表按文件名查找，每页 20 项，只读取摘要；打开某一项才读取其页面并恢复至队列。活动任务受永久删除保护，历史不会自动过期。可恢复内容包括原始逐页文本、手动校对前缀、表格结构与保存的整理设置。恢复整理设置会影响当前工作区，未实现逐任务独立设置。

自动导出默认关闭，启用后记住目录和格式。每个完整文件先保存结果再导出；目标目录会在开始前检查。自动导出不覆盖同名文件，按文件生成，PDF 内表格按现有合并设置处理。多张图片之间的合并仍通过手动导出。暂停/取消的部分结果保留并支持手动导出。

导出失败与识别失败分开，失败可重试导出并继续处理其他文件。部分格式被跳过时，不将该任务标记为全部导出成功。

## 尚需 CI / 目标机验证

本地 Playwright 缺少 Chromium，尝试安装后下载失败。因此不能声称浏览器布局测试通过。CI 保留原有滚动末端断言，并加入真实 IndexedDB 中“清理队列→重载页面→历史打开→表格行数完整”的检查。

未在本地构建原生 Windows / Linux 安装包，未用真实 Paddle 模型完成目标机识别验收。请沿用原有 Actions 构建 Windows x64、普通 Linux AppImage 与 WebKitGTK 4.0 glibc 2.28 AppImage。

目标机建议验收：

1. 升级后打开旧队列，确认现有结果与校对内容正常。
2. 识别一份文本 PDF、一份扫描 PDF 和一张表格；移除队列并关闭，重启后从历史打开并导出，确认文本与表格结构完整。
3. 更换或暂时移走原始文件，确认历史仍能打开和导出；重新识别仍要求原文件可访问。
4. 开启自动导出两种格式，观察每本完成即生成文件。模拟目标目录不可写，确认结果保留、下一项继续，修复目录后仅重试导出。
5. 在历史中勾选已移出的任务永久删除，确认提示未导出数量；当前队列项不可永久删除。

历史仍属于本机应用数据，不是外部备份。升级无法恢复旧版已删除的结果；清除应用数据会清除历史。重要内容应另行导出，不建议旧版本重新操作同一数据目录。
